# Open-source plan and dependency disclosure

## Release scope

Haoming's team will publish the exploration harness, frozen experiment configuration, policy adapters, unit tests, deterministic synthetic data, query-level traces, aggregate results, figures and reproduction instructions represented in this attachment. The release is designed so that another researcher can replace a search policy without changing the hidden-label boundary, query budget, held-out loss split or preregistered discovery gate.

Future device-owner calibration files are outside the public scope unless the owner grants redistribution permission. If hardware experiments are added later, the public interface will retain hashes, schema definitions and evaluation code while respecting any access restrictions on raw calibration records.

## Data provenance

No external scientific dataset, private dataset, commercial API or closed-source model is used. Candidate circuits, optical-loss schedules, query traces and result tables are generated by the included code from the frozen seeds and configuration. The exact generation route is recorded in `reproducibility/README.md` and `reproducibility/config/experiment.json`.

## Third-party dependencies

The dependency graph is locked in `reproducibility/uv.lock`. The principal scientific dependency is `perceval-quandela==1.2.4`, used to construct the linear-optical components and calculate ideal unitary matrices. NumPy 2.5.2 supports the disclosed loss transformation and metrics; Matplotlib 3.10.5 renders the figures. Perceval remains subject to its own MIT licence and its source code is not redistributed here.

Primary dependency references:

- https://perceval.quandela.net/docs/v1.2/
- https://github.com/Quandela/Perceval
- https://pypi.org/project/perceval-quandela/1.2.4/

## Reproducibility commitment

The delivered configuration fixes candidate-pool size, query budget, warm-up count, random seeds, loss distributions, utility weights, bootstrap count and discovery thresholds before evaluation. The package preserves all 1,728 oracle queries and the post-freeze held-out evaluations. A failed gate remains a first-class output and is not relabelled after inspection.
