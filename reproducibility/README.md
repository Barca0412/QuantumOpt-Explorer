# QuantumOpt-Explorer preliminary experiment

This package contains an actually executed, deterministic proof-of-mechanism for
budgeted search over a restricted four-mode linear-optical circuit grammar. It uses
Quandela Perceval 1.2.4 to construct every beam-splitter/phase-shifter layer and to
compute its unitary matrix. NumPy is used only to apply the disclosed mode-loss
matrices and calculate normalized process fidelity, mean single-photon survival,
search statistics, and bootstrap intervals.

The experiment is a simulator study, not a hardware result and not a claim of a new
quantum-optics discovery. The fixed calibration target is generated by a disclosed
five-layer circuit. The task is to find a compact approximation that remains useful
after a distribution shift to stronger, asymmetric held-out loss.

## One-command reproduction

Requirements: `uv` and a Python version in the range 3.12-3.14. Internet access is
needed only for the first dependency installation.

```bash
./reproduce.sh
```

The script installs exactly the dependency graph in `uv.lock`, runs unit tests,
executes all 12 paired episodes for three policies, regenerates the raw data, tables,
figures and English reports, and checks the output invariants.

To run the stages separately:

```bash
uv sync --frozen
uv run --frozen python -m unittest discover -s tests -v
uv run --frozen python src/quantumopt_experiment.py \
  --config config/experiment.json --output-root .
uv run --frozen python src/qa_outputs.py \
  --root . --config config/experiment.json
```

## Frozen comparison

- Policies: uniform random search; nearest-neighbour greedy search; and
  Budget-Aware Diversity Search (`bads`), a project-specific acquisition rule.
- Fairness: the three policies see the same candidate pool, target, training loss
  schedule, six warm-up queries, random seeds and 48-query budget in each episode.
- Information boundary: only training-loss oracle summaries are available during
  search. Held-out loss is applied after the training-selected candidate and Pareto
  archive have been frozen.
- Primary quantity: held-out worst-quartile normalized process fidelity. Mean
  single-photon survival is a preregistered non-inferiority guardrail.
- Positive gate: `bads` must beat both baselines by at least 0.01 fidelity with the
  lower endpoint of the paired 95% bootstrap interval above zero, while its paired
  held-out success difference must have a lower endpoint of at least -0.01.
- Negative outcome: failure of any part of that gate is retained and explained; it is
  not converted into a post-hoc success claim.

The scalar training acquisition utility is

`0.75 * fidelity_q25 + 0.20 * success_q25 + 0.05 * compactness`,

where `compactness = 1 - component_count / 30`. The separate physical metrics are
always retained, so this convenience utility cannot conceal their trade-off.

## File map

This is a size-constrained preliminary-round attachment. The complete query log and
loss schedule are supplied losslessly, in gzip form, in the sibling `evidence/`
directory. Running `./reproduce.sh` creates the full `raw/` and `figures/` directories
described below. The generated bulk files are not duplicated in the submitted ZIP.

- `config/experiment.json`: frozen seeds, budgets, loss distributions and gate.
- `src/quantumopt_experiment.py`: simulator, policies, statistics and figure/report generation.
- `tests/`: deterministic unit and invariance tests.
- `raw/candidate_pool.jsonl`: generated candidate grammar for every episode.
- `raw/loss_schedules.csv`: generated exact training and held-out optical-loss samples.
- `raw/query_log.jsonl`: generated auditable record for every oracle query.
- `raw/query_pattern_metrics.csv`: generated per-loss-pattern metrics behind every query.
- `raw/final_pattern_metrics.csv`: generated post-freeze evaluation of selected candidates and Pareto archives.
- `results/`: episode summaries, aggregate metrics, paired comparisons, learning curves and Pareto sets.
- `figures/`: generated plots built only from saved result tables.
- `REPORT.md`: English preliminary experimental report generated from actual outputs.
- `NEGATIVE_RESULTS.md`: explicit null/failure interpretation generated from the preregistered gate.
- `environment.txt` and `uv.lock`: environment and dependency provenance.
- `../SHA256SUMS.txt`: integrity manifest for every delivered file.


## Simulator boundary and limitations

Perceval computes each ideal layer unitary. The current loss oracle then inserts a
diagonal amplitude-transmission matrix after every layer. This is an explicit
single-photon linear-loss model; it does not simulate partial distinguishability,
multi-photon interference, detector dark counts, source impurity, fabrication drift,
or a laboratory device. The generated candidate pool is a finite calibration corpus
around one disclosed target and therefore cannot establish globally novel topology.
These limitations are carried into `REPORT.md` and `NEGATIVE_RESULTS.md`.

## Open-source boundary

The harness, configuration and generated synthetic traces are intended for public
release. No API keys, proprietary data or closed-source models are used. The code is
MIT-licensed; generated data and reports use the licences in `DATA_LICENSE.md`.
Future hardware calibration files, if introduced, must be distributed only with the
device owner's permission and are outside this package.
